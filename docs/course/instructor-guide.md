# 강사용 가이드

## 한 강의의 기본 진행

1. 5분: 문제 상황과 변경 요구사항 제시
2. 10분: 적용 전 코드를 실행하고 실패 테스트 관찰
3. 15분: 구조도와 소유권/trait 경계 설명
4. 20분: 적용 후 코드를 단계별로 리팩터링
5. 10분: 전후 테스트와 트레이드오프 토론
6. 20분: 실습 및 확장 요구사항

## 질문 순서

- 무엇이 변경되는가?
- 누가 상태와 생명주기를 소유하는가?
- 새 구현을 추가할 때 기존 호출부를 바꿔야 하는가?
- 오류와 취소는 어느 경계에서 표현되는가?
- 이 패턴을 제거하면 무엇이 더 단순해지는가?

## 프로젝트 checkpoint

- 생성: Factory/Builder로 구성 변경을 격리했는가?
- 구조: Adapter/Facade 경계가 외부 오류를 보존하는가?
- 행동: Strategy/State/Command가 동일 계약 테스트를 갖는가?
- Rust 고유: enum/typestate가 실제 불변식을 표현하는가?
- 동시성: shutdown, cancellation, join의 소유자가 명확한가?

## 평가 기준

패턴 이름을 맞히는 것보다 적용 전후의 변경 영향, 테스트 가능성, 소유권 경계, 패턴을 쓰지 않을 때의 비용을 설명하는지를 평가한다.
